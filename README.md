# Лабораторная работа №5. Создание базовой RAG-системы

## Цель работы

Получить практические навыки подключения большой языковой модели (LLM), подготовки текстовой базы знаний, реализации поисковых методов и создания RAG-системы, которая отвечает на вопросы по загруженным материалам и указывает источники.

## Постановка задачи

Разработать локальную RAG-систему для ответов на вопросы по учебному пособию «Устройство и работа поршневых ДВС». Система должна извлекать релевантные фрагменты текста, передавать их языковой модели и формировать краткий и развёрнутый ответ. Список источников должен формироваться программно, без генерации ссылок самой LLM.

Для расширенного варианта лабораторной работы дополнительно реализованы/предусмотрены **три метрики качества поиска** (`Recall@k`, `Precision@k`, `MRR@k`) и **гибридное ранжирование RRF**. Семантический чанкинг в этой версии не используется.


## Используемые технологии

## 1. Подключение к языковой модели

В качестве LLM выбрана локальная **Qwen2.5:3b**, запускаемая через **Ollama**. Подключение реализовано посредством `ChatOllama`:

Параметр `temperature=0` выбран для уменьшения вариативности ответов. Это не гарантирует полной детерминированности, но облегчает сравнение запусков.

------------------------------------------------------------
Вопрос: Почему небо синее?
Ответ: Небо кажется синим из-за процесса, который называется обратной рассеянием Дрейка-Эймсона. Когда солнечные лучи попадают в атмосферу Земли, молекулы газов в атмосфере отражают и поглощают свет. Большая часть красного света отражается меньше, а зеленый и синий свет отражается больше, что делает небо похожим на синий цвет. Это объясняет, почему небо кажется синим, хотя солнце само по-прежнему выглядит красным или оранжевым.
------------------------------------------------------------

Вопрос: Как работает паровой двигатель?
Ответ: Паровой двигатель - это старый тип двигателя, основанный на использовании пара для создания энергии. Вот основные этапы его работы:

1. Входящий водяной поток нагревается в котле, создавая пар.

2. Пар затем под давлением направляется в паровой двигатель.

3. В паровом двигателе пар проходит через ряд труб, называемых паровыми колесами или паровыми колпаками. Это создает вращение.

4. Вращение паровых колес приводит к вращению втулки, которая в свою очередь приводит к вращению колеса, которое может быть приводом для других машин или механизмов.

5. В конце цикла, пара остывает и конденсируется обратно в воду, которая затем возвращается в котел для повторного использования.

Паровой двигатель был одним из первых и наиболее распространенных двигателей в истории, но его роль в современном мире значительно уменьшилась с развитием более эффективных и мощных двигателей, таких как внутренние двигатели и электродвигатели.
------------------------------------------------------------

Вопрос: Что такое инерционное звено первого порядка?
Ответ: Инерционное звено первого порядка - это элемент управления, который можно рассматривать как простейший пример инерционного элемента. Это устройство, которое не изменяет свой угол поворота, если не будет непосредственно воздействовать на него внешняя сила. 

В контексте автоматического управления, инерционное звено первого порядка обычно используется в качестве модели для простых систем, которые не реагируют на изменения скорости или скорости изменения, а только на текущее значение входного сигнала. 

Это звено характеризуется его прямолинейной зависимостью от входного сигнала, и его характеристики определяются только одним параметром - моментом инерции.

## 3. Предобработка и RecursiveCharacterTextSplitter

Для разбиения используется `RecursiveCharacterTextSplitter` с параметрами:

```python
splitter = RecursiveCharacterTextSplitter(
    chunk_size=1100,
    chunk_overlap=150,
    separators=["\n\n", "\n", ". ", " ", ""],
)
```

- `chunk_size=1100` — целевой максимальный размер фрагмента в символах;
- `chunk_overlap=150` — перекрытие между соседними фрагментами;
- последовательность разделителей помогает по возможности сохранять границы абзацев и предложений.

В текущей реализации разбиение выполняется **постранично**, поэтому для каждого чанка можно сохранить номер страницы первоисточника. Поля чанка:

```json
{
  "idx": 12,
  "source": "ДВС.pdf",
  "page": 13,
  "text": "..."
}
```

## 7. Dense-поиск и оценка Recall/Precision/MRR (дополнительный пункт)

### 7.1. Реализация Dense Retrieval

**Dense Retrieval** — метод семантического поиска, основанный на преобразовании текстов и запросов в векторные представления (эмбеддинги).

Для реализации поиска используется модель `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, а хранение и поиск векторов осуществляются с помощью ChromaDB.

Принцип работы:

1. Вопрос пользователя преобразуется в векторное представление.
2. ChromaDB сравнивает вектор вопроса с векторами сохранённых чанков.
3. Находятся наиболее близкие по смыслу фрагменты.
4. Возвращаются тексты найденных чанков и их метаданные.

Преимуществом Dense Retrieval является возможность находить релевантную информацию даже при отсутствии точного совпадения слов запроса и документа.

### 7.2. Метрики оценки качества

Для оценки качества поиска используется тестовая выборка из 15 вопросов с заранее определёнными релевантными чанками (`golden_chunks`).

Оценка проводится при трёх значениях количества возвращаемых документов:

- `k = 1`
- `k = 3`
- `k = 5`

Помимо обязательной метрики Recall@k, рассчитываются дополнительные метрики Precision@k и MRR@k.

**Recall@k (полнота поиска)** — доля всех релевантных документов, найденных среди первых k результатов.

$$
Recall@k = \frac{|Retrieved@k \cap Relevant|}{|Relevant|}
$$

**Precision@k (точность поиска)** — доля релевантных документов среди первых k найденных результатов.

$$
Precision@k = \frac{|Retrieved@k \cap Relevant|}{k}
$$

**MRR@k (Mean Reciprocal Rank)** — среднее обратное значение позиции первого релевантного документа.

$$
MRR@k = \frac{1}{N}\sum_{i=1}^{N}\frac{1}{rank_i}
$$

где:

- `N` — количество тестовых вопросов;
- `rank_i` — позиция первого релевантного документа для вопроса `i`;
- если релевантный документ не найден среди первых k результатов, его вклад в MRR равен нулю.

Для каждой метрики вычисляется среднее значение по тестовой выборке.

**4. Выбор параметра k.**

## 8. Sparse-поиск (BM25) и оценка качества

### 8.1. Реализация Sparse Retrieval

**Sparse Retrieval** — метод поиска документов, основанный на анализе совпадений слов и терминов между запросом пользователя и текстовыми фрагментами.

В рамках лабораторной работы реализован лексический поиск с использованием алгоритма **BM25 (Best Matching 25)** из библиотеки `langchain-community`.

В отличие от Dense Retrieval, который использует векторные представления текста, BM25 оценивает релевантность документов на основании частоты встречаемости слов, их значимости в коллекции и длины документов.

Принцип работы BM25:

1. Текстовые фрагменты проходят токенизацию — разбиение на отдельные слова.
2. Для каждого документа рассчитываются статистические характеристики встречаемости терминов.
3. При поступлении запроса выполняется его токенизация.
4. BM25 рассчитывает оценку релевантности документов относительно запроса.
5. Документы сортируются по убыванию оценки и возвращаются первые `k` результатов.

Для реализации использован `BM25Retriever`.

Токенизация выполняется с приведением текста к нижнему регистру:

```python
def tokenize(text):
    return re.findall(r"[^\W_]+", text.lower(), flags=re.UNICODE)
```

Создание ретривера:

```python
from langchain_community.retrievers import BM25Retriever

retriever = BM25Retriever.from_documents(
    docs,
    preprocess_func=tokenize,
)
```

Преимуществом BM25 является эффективность при поиске конкретных технических терминов, названий, обозначений и ключевых слов.

При этом метод ограничен лексическим соответствием: разные словоформы и синонимы могут ухудшать результаты поиска.

## 9. Гибридный поиск (RRF) и оценка качества (дополнительный пункт)

### 9.1. Реализация Hybrid Retrieval

**Hybrid Retrieval** — гибридный метод поиска, объединяющий результаты семантического (Dense Retrieval) и лексического (Sparse Retrieval) поиска.

Основная идея гибридного подхода заключается в использовании преимуществ двух методов:

- **Dense Retrieval** позволяет находить документы по смысловой близости, даже при отсутствии точных совпадений слов.
- **Sparse Retrieval (BM25)** эффективно находит документы по конкретным терминам, названиям и ключевым словам.

Для объединения результатов реализован алгоритм **Reciprocal Rank Fusion (RRF)**.

В отличие от простого объединения списков найденных документов, RRF учитывает позиции документов в результатах каждого метода.

### 9.2. Алгоритм Reciprocal Rank Fusion

RRF вычисляет итоговую оценку релевантности документа на основании его позиций в результатах нескольких поисковых алгоритмов.

Формула RRF:

$$
RRF(d) = \sum_{r \in R} \frac{1}{C + rank_r(d)}
$$

где:

- \(d\) — найденный документ;
- \(R\) — набор поисковых методов;
- \(rank_r(d)\) — позиция документа в выдаче метода \(r\);
- \(C\) — константа сглаживания, равная 60.

Принцип работы алгоритма:

1. Выполняется Dense-поиск по ChromaDB.
2. Выполняется Sparse-поиск с помощью BM25.
3. Для каждого найденного документа определяется его позиция в обоих списках.
4. Вычисляется итоговый RRF-балл.
5. Документы объединяются с удалением дубликатов.
6. Результаты сортируются по убыванию RRF-балла.
7. Возвращаются первые `k` документов.

Чем выше документ находится в результатах поиска, тем больший вклад он вносит в итоговую оценку.

Если документ встречается в результатах обоих методов, его итоговый балл складывается из двух составляющих.

**Реализация RRF:**

```python
scores = {}
matched = {}

for ranked in (dense, sparse):
    for rank, doc in enumerate(ranked, start=1):
        idx = doc.metadata["idx"]

        scores[idx] = (
            scores.get(idx, 0.0)
            + 1.0 / (60 + rank)
        )

        matched[idx] = doc

order = sorted(
    scores,
    key=lambda idx: (-scores[idx], idx),
)

return [matched[idx] for idx in order[:k]]
```

Для формирования итогового рейтинга используются первые 20 результатов каждого ретривера (при `k ≤ 20`).

Такой подход позволяет учитывать документы, которые могли оказаться за пределами первых пяти результатов одного из методов.

### 10.2. Реализация обработки недостатка информации

В итоговом RAG-пайплайне языковая модель получает исходный вопрос пользователя и фрагменты документов, найденные ретривером.

Для предотвращения генерации недостоверной информации используется инструкция отвечать исключительно на основании предоставленных фрагментов.

Если найденные документы не содержат необходимых сведений, модель должна сообщить о невозможности сформировать обоснованный ответ.

Ожидаемый результат:

```text
Краткий ответ: Недостаточно данных
Полный ответ: Данных для ответа недостаточно
```

Для обеспечения единого формата отказа в программе предусмотрена дополнительная нормализация ответа:

```python
if short.strip().lower() == "недостаточно данных":
    full = "Данных для ответа недостаточно"
```

Таким образом, если модель определила недостаточность контекста в кратком ответе, полный ответ приводится к установленной формулировке.

При этом нормализация не определяет самостоятельно, достаточно ли информации в найденных документах: решение о необходимости отказа принимает языковая модель.

### 10.6. Оценка успешности обработки вопросов без ответа

$$
Accuracy_{\text{outliers}} =
\frac{N_{\text{correct}}}{N_{\text{outliers}}}
$$

где:

- \(N_{\text{correct}}\) — количество корректных отказов;
- \(N_{\text{outliers}}\) — общее количество вопросов без ответа.

В проведённом эксперименте:

- всего проверено 2 вопроса;
- корректно обработано 2 вопроса;
- неправильных фактических ответов не получено.

Следовательно:

$$
Accuracy_{\text{outliers}} = \frac{2}{2} = 1.0
$$

**Доля корректных отказов составила 100% на двух тестовых вопросах.**

При этом данный результат характеризует только проведённые испытания и не гарантирует корректную обработку любых вопросов, отсутствующих в базе знаний.

## 11. Выбор лучшего метода поиска и построение RAG-пайплайна

### 11.1. Сравнение методов поиска

1. **Dense Retrieval** — семантический поиск с использованием векторных представлений текста и ChromaDB.
2. **Sparse Retrieval (BM25)** — лексический поиск на основе статистической оценки соответствия терминов.
3. **Hybrid Retrieval (RRF)** — гибридный поиск, объединяющий результаты Dense Retrieval и BM25 с учётом позиций документов.

Оценка проводилась на тестовой выборке из 15 вопросов по учебному пособию «Устройство и работа поршневых ДВС».

### 11.3. Настройка выбранного ретривера

Для построения итогового RAG-пайплайна используется алгоритм BM25.

Исходными данными являются текстовые чанки, полученные при обработке учебного пособия.

Каждый чанк содержит:

- `idx` — уникальный индекс;
- `text` — текст фрагмента;
- `source` — название исходного документа;
- `page` — номер страницы.

Для работы BM25 данные преобразуются в объекты `Document` библиотеки LangChain.

Создание ретривера:

```python
from langchain_community.retrievers import BM25Retriever

def bm25_db(docs):
    return BM25Retriever.from_documents(
        docs,
        preprocess_func=tokenize,
    )
```

При поступлении пользовательского вопроса ретривер выполняет поиск релевантных фрагментов.

В итоговой системе установлено значение `k = 5`.

Это означает, что для формирования ответа выбираются пять наиболее подходящих документов.

**Получение релевантных чанков:**

```python
bm25 = bm25_db(documents(load_chunks()))

bm25.k = 5

found = bm25.invoke(question)
```

Каждый найденный документ содержит текст фрагмента и метаданные, необходимые для формирования ссылок на источники.

### 11.6. Формирование списка источников

Одним из требований лабораторной работы является формирование ответа со ссылками на найденные документы.

При этом **список источников не должен генерироваться языковой моделью**.

Для выполнения этого требования источники формируются непосредственно в Python на основании метаданных найденных чанков.

```python
print("\nИсточники:")
```

Это позволяет пользователю определить, какие фрагменты использовались при формировании контекста.

Поскольку источники извлекаются непосредственно из метаданных, языковая модель не может самостоятельно изменять их номера или названия.

При этом найденные документы не обязательно содержат ответ. Если модель сообщает о недостатке информации, список следует рассматривать как результаты поиска, а не как подтверждающие источники.

На основании проведённых экспериментов выполнено сравнение трёх методов поиска: Dense Retrieval, Sparse Retrieval (BM25) и Hybrid Retrieval (RRF).

Для выбора основного ретривера использована метрика Recall@5, поскольку при ответах на вопросы, требующие нескольких фрагментов, важна полнота извлечённой информации.

Наибольшее значение Recall@5 продемонстрировал алгоритм **BM25 — 0.7333**.

Гибридный поиск RRF показал наилучшее значение MRR@5 = 0.6378, однако по полноте поиска уступил BM25.

Поэтому для построения итогового RAG-пайплайна выбран метод Sparse Retrieval.

Реализован механизм автоматического выбора ретривера и сохранения результата в `best_method.txt`.

На основе BM25 организованы поиск пяти релевантных фрагментов, формирование контекста для языковой модели Qwen2.5 и программное добавление источников.

Таким образом, подготовлен RAG-пайплайн, использующий метод извлечения документов, показавший наилучшее качество по выбранному критерию.

## 12. Финальная RAG-система и генерация ответов с источниками

### 12.1. Архитектура итоговой RAG-системы

На заключительном этапе лабораторной работы реализована полноценная RAG-система, объединяющая поиск информации в базе знаний и генерацию ответов с использованием локальной языковой модели.

Для построения системы используются следующие компоненты:

- **Ollama** — локальный запуск языковой модели.
- **Qwen2.5:3b** — генерация ответов на вопросы пользователя.
- **LangChain** — взаимодействие с языковой моделью и поисковыми компонентами.
- **ChromaDB** — хранение векторных представлений текстовых фрагментов.
- **BM25** — основной метод поиска, выбранный по результатам оценки качества.
- **Python** — формирование контекста, обработка ответов и добавление источников.

В качестве базы знаний используется учебное пособие «Устройство и работа поршневых ДВС».

**Архитектура итогового RAG-пайплайна:**

```text
            Вопрос пользователя
                    |
                    v
          Выбор метода поиска
                    |
                    v
         Sparse Retrieval (BM25)
                    |
                    v
         Извлечение TOP-5 чанков
                    |
                    v
       Формирование контекста
                    |
                    v
       Промпт: вопрос + контекст
                    |
                    v
          Qwen2.5:3b (Ollama)
                    |
                    v
          Генерация JSON-ответа
                    |
                    v
       Проверка структуры ответа
                    |
          +---------+---------+
          |                   |
          v                   v
     Краткий ответ       Полный ответ
          |                   |
          +---------+---------+
                    |
                    v
      Добавление списка источников
                    |
                    v
            Итоговый ответ
```

При поступлении запроса система выполняет поиск пяти наиболее подходящих фрагментов в базе знаний, формирует из них контекст и передаёт его языковой модели вместе с вопросом пользователя.

Модель генерирует ответ в двух форматах:

1. **Краткий ответ** — сжатое изложение основной информации.
2. **Полный ответ** — более подробное объяснение.

Источники добавляются программно на основании метаданных найденных документов.

Таким образом, языковая модель отвечает за генерацию текста, а Python — за получение и отображение сведений об использованных фрагментах.

Важным требованием лабораторной работы является формирование ответа со ссылками на найденные документы.

В реализованной системе ссылки на источники не генерируются языковой моделью.

После получения ответа программа использует метаданные найденных чанков:

- `idx` — индекс фрагмента;
- `source` — название исходного документа;
- `page` — номер страницы.

На основании этих данных формируется список источников.

Например:

```text
Источники:
- [12] ДВС.pdf, стр. 13

- [66] ДВС.pdf, стр. 35
- [127] ДВС.pdf, стр. 63

```

Такой подход исключает генерацию вымышленных номеров страниц и индексов чанков языковой моделью.

При этом необходимо различать **найденные источники** и **подтверждающие источники**.

Программное добавление метаданных гарантирует корректное указание происхождения найденных фрагментов, но не подтверждает, что каждый из них действительно содержит доказательства утверждений языковой модели.

Для повышения достоверности ответов в дальнейшем может применяться дополнительная проверка соответствия ответа найденному контексту.

### 3.5. Выбор итогового метода поиска

Для выбора поискового алгоритма установлен приоритет метрики Recall@5.

Это связано с тем, что в тестовой выборке присутствуют вопросы, требующие информации из нескольких чанков учебного пособия.

Поэтому основная задача ретривера — извлечь как можно больше релевантных фрагментов.

Наибольшую полноту показал метод **BM25 с Recall@5 = 0.7333**.

При этом гибридный RRF продемонстрировал более высокое значение MRR@5, что делает его перспективным вариантом для дальнейшего улучшения ранжирования.

## 4. Вывод по сравнению методов

- **Dense Retrieval** может быть эффективнее на отдельных вопросах, требующих поиска по смысловой близости.

Для итогового RAG-пайплайна выбран алгоритм BM25, поскольку он продемонстрировал наибольшую полноту извлечения документов.

Таким образом, эксперимент подтвердил, что универсального поискового метода, превосходящего остальные по всем характеристикам, нет. Выбор алгоритма зависит от задач RAG-системы и приоритетных метрик качества.

# Ответы на контрольные вопросы

### 1. Что такое LLM?

**LLM (Large Language Model)** — большая языковая модель, обученная на значительных объёмах текстовых данных и предназначенная для обработки и генерации естественного языка.

LLM способна отвечать на вопросы, пересказывать тексты, выполнять перевод, классификацию и другие задачи обработки языка.

Работа большинства современных LLM основана на архитектуре Transformer.

В рамках лабораторной работы используется языковая модель **Qwen2.5:3b**, запущенная локально через Ollama.

### 2. Какие существуют проблемы при использовании предобученных LLM?

Основные проблемы:

1. **Галлюцинации** — генерация правдоподобных, но недостоверных утверждений.
2. **Ограниченная актуальность знаний** — модель не обладает информацией обо всех событиях после завершения обучения.
3. **Ограниченное контекстное окно** — невозможно передавать произвольно большие объёмы текста.
4. **Зависимость от промпта** — изменение формулировки вопроса может влиять на качество ответа.
5. **Вычислительные затраты** — для работы крупных моделей требуются значительные аппаратные ресурсы.
6. **Нестабильность формата ответа** — модель может нарушать заданную структуру вывода.

Технология RAG позволяет частично снизить эти проблемы за счёт передачи информации из внешней базы знаний.

Однако даже при использовании RAG модель может формировать неподтверждённые утверждения, если найденный контекст недостаточно релевантен.

### 3. Что такое RAG-система? Какие шаги она обязательно включает?

**RAG (Retrieval-Augmented Generation)** — подход к генерации ответов, при котором языковая модель использует информацию, предварительно найденную во внешней базе знаний.

Основные этапы построения RAG-системы:

1. Загрузка исходных документов.
2. Извлечение и очистка текста.
3. Разбиение текста на чанки.
4. Индексация документов для поиска.
5. Получение пользовательского запроса.
6. Поиск релевантных чанков.
7. Формирование промпта с найденным контекстом.
8. Генерация ответа языковой моделью.

Дополнительно могут выполняться проверка корректности ответа, оценка его достоверности и добавление ссылок на источники.

Основным преимуществом RAG является возможность использовать внешнюю информацию без необходимости дополнительного обучения языковой модели.

### 4. Что такое чанкинг? Какие виды чанкинга бывают и на что он влияет?

**Чанкинг (Chunking)** — процесс разделения большого документа на небольшие текстовые фрагменты, которые используются для индексации и поиска информации.

Основные подходы к чанкингу:

1. **Fixed-size chunking** — разбиение текста на фрагменты фиксированной длины.
2. **Recursive chunking** — рекурсивное разбиение по разделителям с сохранением структуры текста.
3. **Semantic chunking** — разделение текста на основании смысловой близости предложений.
4. **Structural chunking** — разбиение по заголовкам, разделам, абзацам и другим элементам структуры документа.

Размер чанков влияет на качество RAG-системы.

Слишком маленькие чанки могут содержать недостаточно контекста для ответа на вопрос.

Слишком большие чанки могут включать много нерелевантной информации, что затрудняет поиск и увеличивает объём контекста, передаваемого языковой модели.

В лабораторной работе используется `RecursiveCharacterTextSplitter` с размером чанка 1100 символов и перекрытием 150 символов.

### 5. Какие существуют подходы к Retrieval?

**Retrieval** — процесс поиска и извлечения релевантной информации из базы знаний.

Основные подходы:

**1. Sparse Retrieval.**

Лексический поиск, основанный на совпадении слов и статистических характеристиках документов.

Пример алгоритма — BM25.

Преимущество заключается в эффективном поиске конкретных терминов и названий.

**2. Dense Retrieval.**

Семантический поиск, использующий векторные представления текста.

Документы и запросы преобразуются в эмбеддинги, после чего выполняется поиск ближайших векторов.

Преимущество заключается в возможности находить информацию по смысловой близости.

**3. Hybrid Retrieval.**

Объединение нескольких поисковых методов, например BM25 и Dense Retrieval.

В лабораторной работе реализован гибридный поиск с использованием алгоритма Reciprocal Rank Fusion.

**4. Retrieval с реранкингом.**

Сначала извлекается расширенный набор кандидатов, после чего дополнительная модель переоценивает их релевантность и изменяет порядок результатов.

Реранкинг применяется для повышения качества ранжирования документов.

### 6. Какие существуют метрики качества RAG?

Метрики качества RAG-системы можно разделить на две группы.

**Метрики качества поиска (Retrieval):**

1. **Recall@k** — доля релевантных документов, найденных среди первых `k` результатов.
2. **Precision@k** — доля релевантных документов среди первых `k` результатов.
3. **MRR@k** — среднее обратное значение позиции первого релевантного документа.
4. **MAP** — средняя точность поиска с учётом позиций всех релевантных документов.
5. **NDCG** — качество ранжирования с учётом позиций и степеней релевантности документов.

**Метрики качества генерации (Generation):**

1. **Answer Correctness** — фактическая правильность ответа.
2. **Faithfulness** — соответствие утверждений ответа предоставленному контексту.
3. **Answer Relevance** — соответствие ответа исходному вопросу.
4. **Answer Completeness** — полнота ответа.
5. **Hallucination Rate** — доля неподтверждённых или недостоверных утверждений.

В рамках лабораторной работы автоматически рассчитываются три метрики качества поиска: **Recall@k, Precision@k и MRR@k**.

Дополнительно экспериментально проверяется способность RAG-системы отказываться от ответа, если необходимые сведения отсутствуют в базе знаний.
